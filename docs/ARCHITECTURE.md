# Architecture and trust boundaries

`core/` remains loader-independent Java17. It validates Unicode, content segments, immutable encoded attachment bytes and bounded PNG/JPEG/GIF decode/compositing. Its local `MockTransport` and `ChatSession` are retained only for the explicitly labelled title-screen preview and tests.

`forge/bridge/RelayRecord` is a bounded binary wire representation, not Java serialization. `BridgeNetwork` defines an optional versioned SimpleChannel and explicit packet directions. Client uploads contain a draft/request nonce and bytes, never trusted player identity, credentials, server paths or external URLs. Chunks, aggregate lengths, sequence, admission queues and per-peer pacing are bounded. The server validates a draft, decodes media off the game thread, derives the player name from the real connection, creates its own canonical event ID, passes the request to the server-owned adapter, and broadcasts validated records. A bounded replay window survives client reconnects.

`forge/server/ServerBridge` owns transport configuration, player allowlists, lifecycle state, workers and transcript. Ordinary Minecraft chat is deliberately not relayed. The official `DiscordBotAdapter` can initialize only on an explicitly opted-in, authenticated dedicated server. It reads a bot secret and channel exclusively from the private server-local `config/discraft-server.properties` file (no environment fallback), uses fixed official REST v10 endpoints and confines media downloads to bounded approved CDN paths without authorization headers or redirects. The adapter validates that its account is a bot. Upstream 401/403 fail closed; transient reads back off with cursor retention, 429 suppresses early retries, and uncertain sends are not automatically repeated. Bot/webhook ingress is ignored to prevent bridge loops. This stage deliberately uses polling rather than Gateway; it has no durable catch-up/exactly-once claim.

`ClientBridge` owns per-connection assemblies, decode queue, ACK futures and server-authored transcript. Connection-generation checks prevent a pending send from reaching a different server; disconnect clears old state. `NativeChat` adds authoritative records to vanilla `ChatComponent` as native text and reserved media cells. Forge chat overlay hooks draw only those cells, reading the pinned 1.20.1 visible-line/scroll fields through Forge's obfuscation-aware reflection helper. Width/font-cell/line-spacing changes rebuild only its own native components, preserve their metadata and ordinary message objects, then invoke native reflow. Native timestamps, text wrapping/history and visible-line selection remain owned by Minecraft. `NativeComposer` adds structured mention selection and revision-scoped media to vanilla `ChatScreen`; a compact smiley picker and spoiler/remove card replace the filename toolbar; ordinary chat and slash commands keep their original transport. Native attachment revisions invalidate cleared/obsolete decodes; Enter waits for validation, captionless attachment Enter has an explicit path before vanilla filters empty input, and Escape/disconnect cancel pending selection work. Send callbacks preserve subsequent drafts/selections. Connection epochs prevent stale callbacks after reconnect. This is an initial visual prototype: extreme widths/spacing, font changes, other chat mods, narration and all interaction permutations are not yet covered. The separate `DisCraftScreen` title-screen preview and earlier standalone regression driver remain available as historical test coverage, not the primary connected-world presentation.

The same JAR loads on a dedicated server without client classes being initialized by server events. Client-only presentation/event subscribers are dist-scoped; client packet handling is guarded by DistExecutor. Actual dedicated startup/shutdown and two-client networking have been tested. Peers without the channel receive only an authorized literal-text fallback; true vanilla interoperability remains unverified. No legacy client's ordinary chat is automatically forwarded.

Test-only code under `src/smoke` is opt-in and excluded from the mod JAR; HTTP/wire tests under `src/test` are not packaged. The explicitly labelled server TEST adapter is accessible only through a smoke-enabled server test mode. Neither test path proves real Discord service delivery. No OAuth flow, personal-account automation, client token field, deployment, Release or other loader/version is included. Resource, delivery and feature limits are documented in [the operator guide](SERVER-BRIDGE.md).

Desktop integration is client-only. `DesktopClipboardService` launches only its own two bundled, dependency-free Java class files in a temporary directory under the same Java runtime. A single bounded pipe handles explicit paste/screenshot commands; the child never polls the clipboard. Each request has a three-second deadline and terminates a stalled helper. Screenshot clipboard ownership is retained until replacement or game shutdown; temporary helper classes are removed at shutdown. Clipboard pixels never enter server configuration or logs. The production game keeps Minecraft’s headless AWT state; only the OS-input acceptance bootstrap initializes desktop AWT early to allow Robot assertions.

Protocol version4 retains the separate bounded guild metadata/thumbnail channel and actor/mention fields, and adds bounded server-only native item ranges/tooltips. Drafts may not supply item metadata. Those fields carry stable server-authorized IDs and explicit UTF-16 ranges. The server derives the sender and main hand from its actual connection and validates target kind, ID and canonical display against a bounded identity registry. Native item labels retain rarity/custom components and native SHOW_ITEM hover without sharing full NBT, book pages or container contents; item PNGs remain Discord-only. Vanilla advancement components are left intact with their own frame colors and hover, without duplicate native announcements. Discord serialization allows only selected Discord user IDs, leaves Minecraft labels literal, and keeps role/everyone parsing disabled. Incoming spoiler filename, `is_spoiler`, or attachment flag8 is normalized before client rendering.

Spoiler policy is stored on each native media tile from its owning record/attachment. The digest-indexed asset table contains only decoded MediaAsset pixels; filenames and spoiler state never enter that shared cache. Reveal state is scoped to the authoritative message UUID, so identical plaintext attachments or emoji cannot reveal another message.

MentionDraft applies explicit replacement ranges from the native EditBox selection/caret, including word/codepoint deletion and native paste. It shifts unaffected selections and invalidates overlapped spans; unknown programmatic changes discard bindings instead of guessing a longest-common-prefix/suffix diff. Selecting two actors with the same visible label therefore retains their different IDs at their actual positions.

Native Enter captures routing intent from the raw selected spans before ClientChatEvent receives vanilla-normalized text. MentionDraft maps spans through pinned1.20.1 trim/normalizeSpace/256-character behavior and verifies the actual event matches that deterministic result. It does not mutate the raw draft merely because the event removed trailing spaces. Unknown transforms, truncation, or changes to a member’s canonical label withdraw ping bindings; an explicit bridge selection retains its intended route without granting arbitrary text ping permission.

Guild catalog metadata and thumbnails are independent of chat history. Server refresh/versioning and bot-role checks precede safe metadata synchronization; clients request only visible IDs and receive bounded, decoded previews through chunk packets. No credential, role-ID list or CDN URL crosses the game channel. Both cache layers enforce positive/negative TTLs, entry/byte/pixel bounds and stale-generation checks. See the operator guide for refresh, failure and preview limits.

Discord item attachments use server-localized immutable semantic tooltip runs derived from the existing sanitized item whitelist. The independently drawn adaptive text PNG has no model hero image; native SHOW_ITEM metadata stays Minecraft-only. Ordinary visibility/HideFlags plus damaged advanced durability are supported, with measured wrapping, explicit overflow rejection and visible bundled-font/missing-glyph fallback. Retained CPU model/resource utilities remain separately tested.

Server localization layers installed selected-locale Forge mod resources beneath ordered local presentation packs. Native Forge English remains the fallback; bridge locale changes never inject a global Language. Namespace/mod ordering and language table/JSON bounds are specified in RESOURCE-PACKS.md. The same immutable index serves event components and item tooltip semantics.
