# Architecture and trust boundaries

`core/` remains loader-independent Java17. It validates Unicode, content segments, immutable encoded attachment bytes and bounded PNG/JPEG/GIF decode/compositing. Its local `MockTransport` and `ChatSession` are retained only for the explicitly labelled title-screen preview and tests.

`forge/bridge/RelayRecord` is a bounded binary wire representation, not Java serialization. `BridgeNetwork` defines an optional versioned SimpleChannel and explicit packet directions. Client uploads contain a draft/request nonce and bytes, never trusted player identity, credentials, server paths or external URLs. Chunks, aggregate lengths, sequence, admission queues and per-peer pacing are bounded. The server validates a draft, decodes media off the game thread, derives the player name from the real connection, creates its own canonical event ID, passes the request to the server-owned adapter, and broadcasts validated records. A bounded replay window survives client reconnects.

`forge/server/ServerBridge` owns transport configuration, player allowlists, lifecycle state, workers and transcript. Ordinary Minecraft chat is deliberately not relayed. The official `DiscordBotAdapter` can initialize only on an explicitly opted-in, authenticated dedicated server. It reads a bot secret from the server environment, uses fixed official REST v10 endpoints and confines media downloads to bounded approved CDN paths without authorization headers or redirects. The adapter validates that its account is a bot. Upstream 401/403 fail closed; transient reads back off with cursor retention, 429 suppresses early retries, and uncertain sends are not automatically repeated. Bot/webhook ingress is ignored to prevent bridge loops. This stage deliberately uses polling rather than Gateway; it has no durable catch-up/exactly-once claim.

`ClientBridge` owns per-connection assemblies, decode queue, ACK futures and server-authored transcript. Connection-generation checks prevent a pending send from reaching a different server; disconnect clears old state. `NativeChat` adds authoritative records to vanilla `ChatComponent` as native text and reserved media cells. Forge chat overlay hooks draw only those cells, reading the pinned 1.20.1 visible-line/scroll fields through Forge's obfuscation-aware reflection helper. Width/font-cell/line-spacing changes rebuild only its own native components, preserve their metadata and ordinary message objects, then invoke native reflow. Native timestamps, text wrapping/history and visible-line selection remain owned by Minecraft. `NativeComposer` adds explicit Minecraft/bridge routing and bounded filename/Attach/Clear controls to vanilla `ChatScreen`; ordinary chat and slash commands keep their original transport. Native attachment revisions invalidate cleared/obsolete decodes; Enter waits for validation, captionless attachment Enter has an explicit path before vanilla filters empty input, and Escape/disconnect cancel pending selection work. Send callbacks preserve subsequent drafts/selections. Connection epochs prevent stale callbacks after reconnect. This is an initial visual prototype: extreme widths/spacing, font changes, other chat mods, narration and all interaction permutations are not yet covered. The separate `DisCraftScreen` title-screen preview and earlier standalone regression driver remain available as historical test coverage, not the primary connected-world presentation.

The same JAR loads on a dedicated server without client classes being initialized by server events. Client-only presentation/event subscribers are dist-scoped; client packet handling is guarded by DistExecutor. Actual dedicated startup/shutdown and two-client networking have been tested. Peers without the channel receive only an authorized literal-text fallback; true vanilla interoperability remains unverified. No legacy client's ordinary chat is automatically forwarded.

Test-only code under `src/smoke` is opt-in and excluded from the mod JAR; HTTP/wire tests under `src/test` are not packaged. The explicitly labelled server TEST adapter is accessible only through a smoke-enabled server test mode. Neither test path proves real Discord service delivery. No OAuth flow, personal-account automation, client token field, deployment, Release or other loader/version is included. Resource, delivery and feature limits are documented in [the operator guide](SERVER-BRIDGE.md).
